# 页面蓝图

这些蓝图是菜单，不是固定模板。每页只解决一个评审问题。

## 封面

目的：识别项目类别、项目名称、答辩人、申请代码和日期。

规则：

- 全部文字居中；
- 项目名称最大；
- 只放五类信息；
- 长标题拆成 2-3 行居中显示；
- 不放摘要、关键词、图形装饰、单位介绍或额外信息。

## 汇报提纲

目的：让评委知道汇报结构。

建议 3-4 个章节：

1. 项目背景与科学问题
2. 研究内容与技术路线
3. 创新点与研究基础
4. 年度计划、经费与风险控制

标题约 80 pt，章节条目约 36 pt。当前章节可用红色或深蓝突出。

## 项目背景 / 必要性

目的：回答“为什么要做”。

结构：

`国家/地方/产业需求 -> 当前瓶颈 -> 本项目切入点`

避免长背景段落，使用 2-3 个短证据标签和一句红色结论。

## 科学问题 / 技术瓶颈

目的：回答“项目到底卡在哪里”。

结构：

- 问题 1：现状/矛盾 -> 拟突破；
- 问题 2：现状/矛盾 -> 拟突破；
- 问题 3：现状/矛盾 -> 拟突破。

安全要求：

- 2-3 个卡片等宽、等高、等间距；
- 标题基线一致；
- 每个问题只保留一句说明和一句突破口；
- 文字必须在卡片内，字号不低于 22 pt。

## 研究内容与技术路线

目的：回答“具体怎么做”。

常用形式：

`材料/对象 -> 表征/机制 -> 调控/优化 -> 验证/应用`

安全要求：

- 流程框等宽；
- 箭头只在框之间；
- 箭头不穿文字；
- 关键输出用红色短语。

## 创新点

目的：回答“新在哪里”。

建议 3 条以内：

- 设计逻辑创新；
- 机制解析创新；
- 性能/应用验证创新。

每条创新用短标题 + 一句解释。底部可放一句红色总结。

## 研究基础与可行性

目的：回答“为什么你能做成”。

可用证据：

- 代表性论文；
- 专利；
- 已有实验方法；
- 平台设备；
- 初步数据；
- 合作或支撑条件。

不要只堆列表，要加一句“这些基础如何支撑本项目”。

## 年度计划 / 预期成果

目的：回答“怎么推进，产出什么”。

常用三年时间线：

- 第一年：材料/体系建立；
- 第二年：机制解析；
- 第三年：性能验证和成果凝练。

成果要数字化：论文、专利、样机、标准、学生、平台或可验证指标。

## 经费预算 / 风险控制

目的：回答“钱是否合理，风险是否可控”。

预算：

- 短答辩用 4-5 条 bar 或列表；
- 不用小字密表。

风险：

`风险 -> 影响 -> 对策/替代路线`

结论示例：

`关键风险可识别、路线可替代、目标可验证。`

## 致谢

目的：正式收尾。

内容：

- 感谢各位专家；
- 敬请批评指正；
- 项目名称或项目类别。

保持干净，不要增加新信息。

## 讲稿蓝图

生成 `答辩讲稿.md`：

```markdown
# 答辩讲稿

总时长：8分钟（含约40秒缓冲）

## 第1页｜封面｜20秒
各位专家好，我是……。我汇报的项目是……，申请代码是……。下面我将围绕项目背景、研究内容、创新基础和风险控制四个方面进行汇报。

转场：首先汇报项目的整体逻辑。
```

时间分配：

- 封面/提纲/致谢：15-25 秒；
- 普通内容页：35-60 秒；
- 核心技术路线或创新页：50-75 秒；
- 总讲稿目标时长应低于总汇报时间 8-12%。
